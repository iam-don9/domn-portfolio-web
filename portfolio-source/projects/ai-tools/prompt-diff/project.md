# 提示词差异对比

## 项目故事

- 项目背景或起点：迭代提示词时经常忘了自己上一版改了什么，结果来回抽卡。需要一种方式把改了哪几个词显式记录下来。
- 项目目标：输入两个提示词版本，输出结构化的差异报告（增、删、改），并标注可能影响的维度。
- 受众或使用场景：自己的迭代流程，也适合团队协作时对齐改动。
- 最终成果：一个 diff 脚本，输出高亮的差异与维度标注。
- 我的具体贡献：差异规则设计、维度映射、脚本实现。

## 工具和方法

- 使用的模型和工具：纯 Python，基于词元与短语两层 diff。
- 关键工作流程：分词 → 对齐 → 标注增删改 → 映射到构图、光线、材质、情绪维度。
- 技术限制：不解语义，只做表层差异。维度标注靠关键词规则。

## 创作过程证据

1. 概念或草图：先画了差异报告的字段。
2. 参考方向：代码 diff 的呈现方式。
3. 提示词或脚本迭代：从整段对比改成短语级对齐。
4. 生成结果对比：同一提示词两组微小改动，diff 能定位到具体词。
5. 人工修改或合成：未做，输出即结果。
6. 最终交付：diff 脚本。

## 关键决策

- 决策 1 及原因：短语级而非词级 diff。词级噪点太多，短语级更能对应一处改动。
- 决策 2 及原因：标注维度而不是打分。打分是伪精确，维度标注让人自己判断。
- 遇到的问题及解决方式：中英文混排对齐错乱。按空格与标点双重切分，保留中文整词。

## 提示词、脚本或配置说明

- 提示词或脚本说明：提示词约定维度词用方括号分组，diff 据此映射到维度。
- 重要参数：对齐窗口 3 个短语，超出视为不相关改动。
- 可复用技巧：迭代要可回溯，diff 是底线工具。
